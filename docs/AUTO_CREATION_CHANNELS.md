# 自动创建的通道降级与恢复

自动创建开启后，网关按已保存的一小时计划运行，不因单个通道过期而关闭整份计划。

| 连接状态 | 自动创建规则 |
| --- | --- |
| 新通道与旧通道均可用 | 新通道每小时最多 19 次，旧通道最多 4 次，总计 23 次 |
| 新通道过期或退出，旧通道可用 | 旧通道每小时最多 5 次，分散在原计划的时间槽中 |
| 旧通道失效 | 暂停创建请求，保留已开启的计划；重新登录后继续 |
| 手动关闭计划 | 保持关闭，登录操作不会重新开启 |

新通道可用性依据本地会话的拒绝标记和到期时间判断。临时续期故障不会直接当作退出。实际创建收到新通道认证失效时，持久化该通道的失效状态，保留旧通道登录态；本次操作不重复创建，后续时间槽使用降级规则。新通道重新登录后，调度器在后续时间槽自动恢复双通道规则。

模式切换不会重排或清空计划，也不会重置滚动一小时的尝试记录。旧通道从降级的 5 次恢复为双通道的 4 次时，原尝试仍计入额度，必要时等待额度释放。Apple 明确限流及更长的 Retry-After 继续生效；重启保留这些记录。

这里的数字是本地自动创建的尝试上限，成功数取决于 Apple 的实际响应、目录确认、库存与容量。创建仍需要旧通道目录来确认账户归属和候选地址；目录连接失效时，新通道有登录态也不会绕过确认继续创建。已生成但待确认的地址、未知远端结果、账户停用或身份变化仍沿用既有处理规则。

旧版本已经关闭的计划与用户主动关闭的计划缺少可靠的区分字段，因此升级不会批量重新开启历史关闭项。仍开启的计划自动采用本规则；历史关闭项由管理员确认后开启。
